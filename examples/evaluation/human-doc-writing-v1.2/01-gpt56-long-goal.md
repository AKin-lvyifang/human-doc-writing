# 让 GPT-5.6 走出 Phase 0，长任务需要写清出口

我们最近在 Codex 里让 GPT-5.6 处理长任务和 Goal 任务，其中一次任务从 Phase 0 开始跑了一整晚，第二天再看，它仍然留在 Phase 0。执行记录一直在更新。模型检查假设，补上测试，寻找新风险，还在继续确认眼前的方案是否可靠。单看每一步都有理由，合在一起却没有停止条件。

一个问题刚处理完，新的问题又会从结果里冒出来。它可能属于未来阶段，可能是生产环境才需要的加固，也可能只是一个值得考虑的可选能力。只要这些问题都被当成当前阶段的工作，Phase 0 的边界就会一圈圈向外扩，做得越久，离出口反而越远。

在我们观察到的这次工作流里，GPT-5.6 会继续为尚未排除的风险寻找证据，它补一次检查，当前疑点解决了，结果又带出另一个方向。原本用来支持决定的推理慢慢开始推迟决定。任务一直有动作，阶段状态没有变化。

测试也会进入同样的循环，最初的测试能够暴露失败、验证修改，这些结果会直接改变下一步。到了后面，测试已经不再产生新证据，模型仍可能换一种方式复查同一个范围。命令和检查角度都变了，对当前交付物的判断却没有变化，继续验证只是重复确认，并没有让任务更接近下一阶段。

只加一句“跑完”或“不要停”解决不了这个问题。这类要求只规定模型要持续完成当前目标，没有替当前目标划边界。若把“不要停”理解成只要还能想到风险就继续做，终止条件反而会给范围扩张提供动力。一整晚的执行时间，也就可能被消耗在不断延长的 Phase 0 里。

长任务需要一个可以执行的阶段出口，当前 Goal 要写清这轮究竟完成什么，Phase 要说明眼下处在哪一步，交付物要能落到具体结果，验收标准则负责判断什么时候算完成。这四件事直接告诉模型，哪些证据足以支持前进，哪些问题不该在这一阶段继续展开。

其中最重要的一条，是给新问题设置进入当前范围的门槛。只有它与当前交付直接相关，已经造成真实失败，或者正在直接阻塞下一步，才转成当前行动。未来阶段可能遇到的问题、生产加固方向和可选能力可以被看见，但不能因为它们存在，就自动占用这一阶段的开发和验证时间。

检查范围也要跟着阶段走。开发过程中，先运行受本次改动影响的最小检查，用它确认这一步是否有效；全量回归留到阶段集成、最终交付，或者公共契约和高风险行为发生变化的时候。检查仍然完整，只是分别放在能够改变判断的时点执行，验证不再提供新证据时，下一步只剩两种。若确实有失败挡住交付，就停止横向扩展，转入根因诊断，查清同一个阻塞为什么一直存在。若没有真实阻塞，就结束当前验证，进入下一阶段开发。继续找一种新的复查姿势，不应成为默认的第三种选择。

阶段出口还会反过来约束模型的深度推理。模型仍然可以发现风险，也可以指出方案边界，但发现不等于立刻实施。推理的任务是帮助当前阶段作出更好的决定，而不是把每一个未来可能性都提前变成今天的工作。这样才能保留深度，同时避免深度变成没有终点的扩张。

这项观察只来自我们使用的一种长任务工作流，不能据此断言 GPT-5.6 在所有任务中都会困在 Phase 0。能直接调整的是任务的组织方式，让当前范围、阶段出口和验证停止条件都可以判断，避免把是否继续完全交给模型临场决定。

下一次启动长任务时，先把 Goal、Phase、交付物和验收标准写到模型能直接执行的程度；开发时只让真实失败和直接阻塞改变当前计划，测试不再产生新证据就收口。模型便能结束无止境的“持续工作”，一段一段地把任务往前交付。
