# GPT-5.6 跑了一整晚，为什么还停在 Phase 0

有一次，我们让 GPT-5.6 在 Codex 里处理一个长任务。它从 Phase 0 开始工作，整晚都没有停。第二天再看，任务仍在 Phase 0。

这个结果很容易被误解成模型卡住了。翻开过程记录，却会看到它一直在干活。它检查假设，补测试，发现新的风险，再想办法证明眼前的方案足够可靠。刚解决一个问题，下一个问题又出现了。

麻烦恰好出在这种认真里。

长任务常常同时摆着几类问题。有些问题会直接影响当前交付，有些属于后续阶段，还有些是面向生产环境的加固或可选能力。它们都值得处理，只是处理时机不同。GPT-5.6 在这次工作流里没有得到清楚的阶段出口，于是每看到一种可能性，都倾向于把它纳入眼前的工作。

范围就这样慢慢长大。当前方案刚经受住一轮检查，模型又会追问另一个边界是否安全。某个测试通过了，它还会换一种方式复查。未来阶段可能遇到的风险，也会反过来成为 Phase 0 继续停留的理由。

深度推理在这里呈现出一种很具体的倾向。它擅长继续寻找尚未被证明的部分，却未必会自行判断一件事已经足够支撑本阶段交付。这个观察只来自我们最近在特定长任务工作流里的使用，不能推成 GPT-5.6 在所有任务中的共同缺陷。但它已经足够提醒我们，长任务不能只写起点和远方，还要写清中途怎样离站。

最先需要钉住的是当前 Goal 和 Phase。Goal 说明这轮工作最终要完成什么，Phase 说明眼下只负责哪一段。再把交付物和验收标准写清，模型才能判断一个新发现应当立即处理，还是留给后面的阶段。

判断标准可以很朴素。一个问题只有在影响当前交付、对应真实失败，或直接挡住后续动作时，才进入当下的行动。未来阶段的能力、生产环境的加固、顺手想到的改进，可以记录下来，却不该悄悄改写现在的范围。

测试也需要同样的边界。开发过程中，先运行受影响的最小检查，看看刚才的改动有没有解决眼前问题。全量回归留到阶段集成、最终交付，或公共契约与高风险行为发生变化的时候。这样做并不会降低要求，它让每次验证都有明确问题，也让验证结果能够推动决策。

还有一个很实用的停止信号。连续检查已经不再产生新证据，结果没有改变判断，也没有暴露真实失败，这轮验证就该结束。若仍有实际阻塞，下一步应转入根因诊断，找到究竟是哪一环挡住了任务。没有阻塞，任务便应进入下一阶段开发。

这条规则能切断一种常见循环。模型为了确认方案，又增加一次测试。新测试只重复旧结论，它便改用另一种角度继续确认。过程看起来越来越严密，交付却没有向前走。只要问一句“这次检查产生了什么新证据”，循环就有了可判断的出口。

我们也重新理解了“跑完”和“不要停”这类指令。它们要求模型持续完成当前目标，不等于授予它无限扩大范围的权力。否则越有耐心的模型，越可能把所有相关风险都背到当前阶段，最后以持续工作代替阶段完成。

长任务当然需要认真。认真还得有边界，有离开的条件。把 Goal、Phase、交付物和验收标准写成同一份约束，再规定哪些问题能进入当前行动，模型才知道什么时候继续查，什么时候诊断，什么时候往前走。

第二天还停在 Phase 0 的那次任务，留给我们的提醒很简单。别只告诉深度推理模型要一直跑，也要告诉它，凭什么可以离开这一站。
