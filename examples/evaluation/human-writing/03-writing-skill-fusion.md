# 个人写作 Skill 之外，还需要一道统一的人味门禁

我们这次整理写作 Skills 时，先处理了一个很具体的旧工具。`khazix-writer` 是为“数字生命卡兹克”设计的公众号 Skill，共有 414 行。它会自动匹配公众号写作，带着固定作者身份、口癖和尾部。现在它已经被移进废纸篓，需要时仍可恢复。

随后装上的 `human-writing` 走了另一条路。最新开源版本是 1.0.0，它面向通用中文创作与改稿，不要求用户模仿卡兹克本人。它先检查现实稿的材料够不够，再处理说话位置、段落推进和中文词序，初稿之后还有七遍改稿与自动检查。它也明确说明，不建立作者画像或个人规则库。

把这两个工具放在一起看，很容易产生一个选择题。写作工具究竟应该记住一个人，还是应该提供任何人都能用的中文写作标准。这个问法会漏掉两类工具承担的工作差异。个人风格和共同质量处在不同位置，解决的也不是同一类问题。

我们自己的 `human-doc-writing` 以渐进式画像为核心。它会按文章类型路由，也会保存用户认可和反感的写作决策。公众号、小红书、产品文档、教程、PRD 和 README 面对的读者不同，承担的任务也不同。一个适合公众号开头的处理，放进 PRD 里可能显得绕。README 需要让人迅速找到安装和使用办法，小红书则更在意信息怎样被读下去。类型卡、确认卡和长文编排，正是在处理这些差别。

画像能回答“这个人习惯怎样写”和“这个场景应该怎样写”。它可以逐步记住哪些表达得到认可，哪些做法令人反感，也能让同一个作者跨文体时保持稳定判断。可画像越细，并不自动保证每篇成稿都自然。不同类型仍可能掉进一些共同的问题。

模型可能用很具体的时间、人物和动作制造可信感，可材料里从来没有这些内容。它也可能每段都说得通，下一段却没有增加新信息。还有一些稿子依靠固定路标推进，或者把普通动作换成商业黑话，最后再用一段整齐的总结收尾。作者身份再准确，这些问题仍会让文章露出明显的模型痕迹。

因此，我们选择保留原有的画像、类型卡、确认卡和长文编排，在成稿外面增加一道统一的人味终审。每种文章仍然保有自己的声音，终审只检查那些跨文体都会损害可信度和阅读感的问题。

终审先看事实和材料。现实稿里的数字、经历和具体动作有没有来路，材料能不能托住文章长度，作者是否把推测写成了事实。接着看段落，每一段是否带来新信息，还是只把上一段换了一种说法。然后再处理假具体、模型路标、商业黑话和机械结尾。遇到问题就回到原句承担的事实和任务，改成普通、准确的话。

统一门禁也要尊重文体。社媒中长文可以使用更严格的散文检查，因为读者要沿着句子和段落一路读下去。README、PRD 和教程承担说明任务，必要的冒号、列表、表格、代码和术语都要保留。格式本身没有错，需要防的是用格式掩盖空话。表格里每一格都没有新增信息，排得再整齐也帮不了读者。

这套融合关系因此很清楚。个人画像负责因地制宜，决定文章要服务谁、采用哪类结构、保留怎样的个人判断。统一终审负责守住共同底线，防止具体场景把模型化问题一并合理化。一个让文章更像这个人，另一个让文章先像人写的。

独立安装的 `human-writing` 仍然有价值。用户想显式调用通用中文创作与改稿时，可以直接选择它。融合后的版本则继续服务个人画像和跨场景写作，让积累下来的偏好进入不同类型的文章，再由统一终审检查成稿。

旧的 `khazix-writer` 被移到废纸篓，也保留了恢复余地。过去的作者设定仍然在，固定人设已经离开默认入口。写作工具可以记住一个人，也可以拥有共同标准。把两者放在正确的层次里，个人风格才不会变成质量豁免，统一检查也不会把所有作者磨成同一种声音。
