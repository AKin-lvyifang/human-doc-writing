# 个人写作画像之外，还要有统一的人味检查

这次整理本机写作工具时，我们把旧的 `khazix-writer` 移进了废纸篓。它一共有 414 行，文件仍然可以恢复。这个 Skill 围绕“数字生命卡兹克”的固定人设写公众号，会自动匹配公众号任务，也包含固定作者身份、口癖和尾部。

人设型 Skill 有清楚的使用范围。目标是持续复现同一位作者时，身份、口吻和收尾都能保持稳定。写作任务扩展到产品文档、教程、PRD、README 和小红书以后，固定人设会进入许多不需要它的场景。不同文体需要的结构、语气和信息密度也会发生变化。

最新开源 `human-writing` 版本是 1.0.0。它面向通用中文创作和改稿，不要求模仿卡兹克本人。写现实内容时，它先检查材料能否支撑文章，再处理作者从什么位置说话、段落有没有继续推进、中文词序是否自然，随后完成七遍改稿和自动检查。

这套方法负责处理多种文体都会遇到的问题。材料里没有的人物和现场不能补成事实，同一个判断不能换几种说法反复出现，普通事情也不需要商业黑话和宏大结尾。它同时保留了一条明确边界，不建立作者画像，也不维护个人规则库。

我们自己的 `human-doc-writing` 从个人画像出发。它会先判断文章类型，再读取该场景下的当前画像和反例。用户认可一篇文章，可以保存其中可迁移的写作选择；用户反感某种写法，也可以把它记录成避坑规则。产品文档、教程、PRD、README、公众号和小红书分别使用适合自己的信息结构。

两套能力负责不同的工作。画像决定这次文章怎样开头，信息按什么顺序展开，哪些地方详写，使用列表还是连续正文，以及事情讲到哪里结束。通用检查负责守住事实和表达的共同边界，避免某种模型化写法因为被画像记录，就在以后反复出现。

这次融合保留了 `human-doc-writing` 原有的画像、类型卡、确认卡和长文编排，并让所有成稿在交付前经过同一道人味终审。公众号仍按公众号的阅读方式写，PRD 仍要支持团队作出决定，README 仍要帮助访客安装和运行。统一检查不会把这些文体改成同一种散文。

终审先看事实和材料。现实稿里的经历和数字要有来源，写到的具体动作与产品状态也要能够核对，文章长度则要和材料数量相称。接着逐段检查内容是否增加了事实，是否说明了新的动作和后果。只把上一段换一种说法的内容会被合并或删除。

后面的编辑会清理没有来源的细节，也会删掉模型常用的转折路标。抽象名词和商业黑话如果没有准确含义，就改回具体动作；内容讲完以后，机械增加的结尾直接删除。公众号等社媒中长文使用更严格的散文检查，README、PRD 和教程则保留导航和执行所需的列表、表格、代码与准确术语。

画像和统一终审发生冲突时，事实与材料要求优先。一个公众号画像可以偏爱具体场景，但材料没有提供人物、对白和动作时，文章不能自行补出现场。一个 README 画像可以偏爱简洁列表，列表里的每一项仍要提供有效信息，不能只把一句空话拆成多行。

最新版 `human-writing` 也继续作为独立 Skill 安装在本机。用户需要通用中文创作或改稿时，可以直接调用它。`human-doc-writing` 则继续服务个人画像和跨场景写作，把通用的人味检查接到每一种类型的交付过程里。

以后使用这套个人写作系统，先根据文章类型和当前画像完成初稿，再核对事实、材料和段落推进，最后运行对应的自动检查。公众号、小红书和技术文档可以保留各自的写法，共同的问题会在交付前被找出来。检查通过以后，正文只保留读者需要看到的内容。
