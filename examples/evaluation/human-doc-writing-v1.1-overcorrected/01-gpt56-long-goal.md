# 让 GPT-5.6 离开 Phase 0，长任务要把阶段出口写进任务

我们最近在 Codex 里用 GPT-5.6 处理长任务和 Goal 任务，遇到过一次停滞。任务从 Phase 0 开始执行，跑了一整晚。第二天打开记录，它仍然停在 Phase 0，后面的开发还没有开始。

执行记录里一直有动作。模型检查假设，补充测试，发现风险，再继续确认当前方案是否可靠。一个问题处理完以后，它又找到另一个问题。有些问题属于后续开发，有些属于生产环境加固，还有一些只是以后可能用到的能力。它们陆续进入当前任务，原来的 Phase 0 便越做越大。

测试也会延长这个过程。一次检查已经支持现有判断，模型仍可能换一个角度复查。新的检查没有暴露失败，也没有推翻假设，执行却继续占用时间。记录看上去很充实，阶段状态始终没有变化。

这种情况和深度推理的工作方式有关。模型愿意寻找遗漏，也愿意把证据追得更完整，这些特点在复杂任务里很有用。问题出在任务只写了一个很远的终点，没有说明眼前这一阶段做到什么程度就可以结束。模型看到新的可能性时，缺少判断处理时机的依据，只能继续把它放进当前范围。

这只是我们在特定长任务工作流里的观察，不能推成 GPT-5.6 处理所有任务时都会遇到的缺陷。这里能够确认的是任务说明缺少阶段出口，文章也只讨论怎样补上这项约束，不评价模型在其他任务里的表现。

一份可执行的长任务需要同时写清 Goal、Phase、交付物和验收标准。Goal 说明这轮工作要得到什么结果，Phase 限定眼下只负责哪一段，交付物让完成结果能够被检查，验收标准负责判断什么时候可以进入下一阶段。这四项共同构成当前工作的范围。

新发现的问题也要经过同一套判断。它直接影响当前交付，已经对应一个真实失败，或者确实挡住了下一步，才转成这一轮的行动。未来阶段可能需要的能力可以记录下来，生产环境加固可以进入后续计划，可选改进也可以留在待办。记录这些事项不等于现在实现它们。

测试范围需要跟着阶段走。开发过程中先运行受影响的最小检查，确认刚才的改动解决了眼前问题，并且没有破坏直接依赖。全量回归留到阶段集成、最终交付，或者公共契约和高风险行为发生变化的时候。每次验证都有明确对象，测试结果才会推动决定。

停止扩展测试也需要一条可判断的规则。新的失败、被推翻的假设、会改变实现选择的结果，都属于新证据。只是更换检查方式后得到同一个结论，没有给下一步带来新的信息。这时继续复查只会增加工作量，不会提高当前阶段的完成度。

验证停止以后，任务只有两种去向。存在真实阻塞，就转入根因诊断，确认失败发生在哪个环节。没有真实阻塞，交付物也满足验收标准，就结束当前 Phase，进入下一阶段开发。任务不需要靠持续增加测试来证明自己还在工作。

“跑完”和“不要停”也要放在这个边界内理解。它们要求模型持续完成已经约定的目标，遇到困难时不要提前退出。它们没有扩大 Goal 和 Phase 的作用。若把所有未来风险都提前纳入当前阶段，任何复杂项目都能不断找到下一项工作。

下一次交给模型长任务时，可以直接把阶段出口写进提示。当前交付满足验收标准，受影响的最小检查已经通过，验证没有提供新证据，也不存在直接阻塞，此时结束当前 Phase 并继续开发。只要有一项没有满足，执行记录也应明确指出缺少的结果。到了约定条件，就进入下一阶段。
