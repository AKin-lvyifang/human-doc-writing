# 写作确认卡

第一轮只发一张用户看得懂的短卡片。先从材料和原文中预填，不让用户填写技术表格。

```text
## 我准备这样写

- 文档：docs/product-overview.md
- 类型：产品白皮书
- 读者：已经在用 Obsidian，但不了解这个插件的人
- 读完后：能理解产品如何工作，并判断是否适合自己
- 覆盖：用户问题、核心工作流、权限边界、当前能力和限制
- 不覆盖：逐条命令手册、完整安装教程
- 结构：模块化长文，正文保留产品全景，细节放附录或链接
- 参考方式：使用你的“产品文档画像”
- 执行方式：主 Agent 统稿；子智能体并行核对产品事实、权限边界和版本状态
- 输出：保留可证实事实，重做结构，直接修改文件

我还需要确认：
1. 路线图只保留摘要，还是完整收入附录？

回复：`开始`、`修改：……` 或 `直接执行`。
```

## 规则

- 没有用户画像时，参考方式写“使用内置初始规则”。
- 短文不显示“结构”和“执行方式”，避免把确认卡写成项目计划书。
- 只有实际使用子智能体时，才显示执行方式。
- 最多列 5 项覆盖内容和 4 项不覆盖内容。
- 最多问 3 个问题；能从材料确认的不要问。
- 不展示 `type_id`、内部文件路径、脚本名、画像存储结构或“统领目标”等内部术语；对用户写成“读完后”。
- 用户已经给出完整要求时，问题栏可以省略。
- 用户回复“确认”也视为“开始”。
