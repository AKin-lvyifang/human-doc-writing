# 中文写作与编辑

让文章有具体的观察、可信的声音、合适的文学表达，让读者愿意读、读得懂。文体、风格、画像和检查都服务这个目的。文学性随场合变化：说明文重准确与明净，叙事重视角与细节，评论重判断与分寸，随笔可以有联想、节奏和余味。

不把所有文章写成同一种克制白话，也不为显得有文采增加辞藻、假经历或固定人设。下面的流程按任务需要使用，不给短文或局部改稿增加全套手续。

## 识别请求

- **写作、改稿**：新写、扩写、压缩、润色、结构调整或换文风。局部改稿保留未要求改动的内容、原作者有效的声音和事实，只检查改动及其衔接。
- **本次借鉴、风格分析**：用于当前任务，默认不保存长期画像。
- **学习、记住、更新画像**：进入画像学习流程；与写作同时提出时，先完成所需学习，再直接写作。
- **查看、删除、恢复画像**：使用画像管理脚本。无对应画像时用通用指导写作，不要求用户先交样文。

只在缺失信息会改变内容方向、关键事实或交付范围，且无法合理推断时提问；等待时继续独立部分。先讨论、只给方案或不修改文件的要求始终适用。

## 写作与编辑

### 1. 决定怎样让读者进入文章

新写或大幅重写时，读取 [文体与场合路由](references/type-router.md) 和选中的实质文体卡，再用 [文风选择](references/style-selection.md) 判断表达方式。在内部明确：

- 读者已经知道什么，为什么此刻会读。
- 读完后应理解、感受到什么，或能完成什么。
- 实际文体、发表场合、作者位置与最值得展开的材料或判断。
- 适合的叙述距离、情绪程度、节奏与修辞分寸。
- 用户要求的范围、篇幅、修改深度和输出位置。

这些是写作选择，不是固定表格。要求清楚时自主起稿，不先交确认卡或要求用户挑风格菜单。确需澄清时参考 [简短澄清](references/brief-template.md)。

平台影响阅读时机、篇幅与呈现；同一平台可以容纳不同文体和声音。文体卡的内容底线始终适用，画像调整默认表达，不替代教程的成功标志、PRD 的规则与验收等必要内容。

### 2. 取用材料与个人偏好

从用户材料、原稿和必要的一手来源取得事实。涉及项目时只读取能确认本篇术语、能力状态与操作的文件，不因写作全面扫描项目。按 [材料与篇幅](references/material-gate.md) 区分现实事实、判断、说明性假设与获准虚构。

画像按下面方式取用，只读本篇相关部分：
1. 当前明确要求优先；事实与授权边界始终保留。
2. 读取存在的 `user/preferences.md`，了解跨场合偏好。
3. 查看 `user/portrait-index.md`，选择文体、用途与读者关系匹配的一份主要正向画像，必要时补一条相容写法，不混合全部画像。
4. 读取适用的避坑画像；避坑也受其场合范围约束。
5. 无匹配画像时，用文体卡和通用创作方法直接写。

旧 `wechat-article`、`xiaohongshu`、`social-article` 画像只在其声明文体、用途和场合匹配时适用。历史公众号复盘画像不自动约束人物稿、散文或其他平台；本次明确文风要求优先于旧画像。

### 3. 构思和成稿

新写或大幅重写时，读取 [创作方法](references/writing-craft.md)。先找到值得表达的观察、关系或问题，再安排读者怎样经历文章。文风体现在取材、揭示顺序、详略、节奏和语言选择中。

- 每段应对理解、叙事、感受或必要的阅读停顿有所贡献，不要求每段都新增事实。
- 允许有效的重复、设问、排比、比喻、留白和照应。按本篇目的选择，不按固定频率安排。
- 文学表达使用材料中有表现力的细节；推测不写成见闻，说明性例子不冒充现实证据。
- 易读来自跟得上的信息顺序、清楚的关系和必要解释；复杂处可以充分展开。
- 不为套画像牺牲事实、读者任务或原稿已经成立的表达。

存在可独立核对的来源域、模块或多份交付物时，按需读取 [长文编排](references/long-form-orchestration.md)。主 Agent 负责整篇声音、结构与最终文件，连续叙事不按小标题分包拼接。

### 4. 从读者位置编辑

成稿后按 [读者编辑](references/human-voice-gate.md) 检查：读者能否进入、跟上、感到作者在意什么，本篇选择的文风是否成立。

先保护有表现力的部分，再修理解断点、事实越界、无效重复和失去分寸的修辞。发现具体问题才回改，无问题不为完成流程强行重写。局部改稿只复查受影响部分。需要查漏时用 [编辑检查表](references/editor-checklist.md)。

脚本辅助定位可疑处，不评定人味、文学性或事实可信度：
- 对本地 Markdown/纯文本完整成稿，使用 `scripts/lint_ai_style.py <文件> --strict` 检查内部过程残留；有明确汉字数下界时可加 `--min-han N`。对话短答或单句改写不为脚本单独建文件。
- `universal`、`social-longform`、`wechat-longform` 是兼容提示档位；审美提示按语境取舍，不要求清零，不因提示分高退稿。
- 多稿疑似共用结构时，可用 `scripts/compare_draft_shapes.py <稿件...>` 辅助比较；段数相同不等于叙事相同，系列文章不必故意长得不同。
- 需要查看改写覆盖时可用 `scripts/de_ai_diff.py --before <原稿> --after <改稿>`；文字变化比例不代表质量。

已有检查仍对应当前文本与参数时复用。只修复确定的问题，不通过改段数、换同义词或改标点迎合指标。

## 学习与维护画像

明确要求学习、记住或更新长期偏好时，读取 [画像学习](references/portrait-ingestion.md)；格式见 [画像模板](references/portrait-template.md)，示意见 [画像示例](references/portrait-example.md)。

从完整可读正文中提炼“创作选择 → 读者效果 → 适用条件”。一篇样文即可形成当前可用画像，不要求补齐样文数量。无法完整读取时说明缺口，不根据摘要猜风格。

- 稳定偏好写入 `user/preferences.md`，只记录用户明确认可的跨场合选择；一次批评或单篇样文不自动升级为普遍禁令。
- 不同场合、声音的画像可并存。新学到的不同写法使用具名画像，不平均混合或静默替换默认画像。
- 补充同一写法时更新相应画像并备份；明确要求替换默认时才替换该文体默认画像。
- 不把样文事实、身份、经历、观点或标志性表达迁入新稿。必要时用少量原创跨题示例说明分寸。
- 当前写作得到反馈时先按授权修稿；只有用户要求记住或调整画像时，才持久保存新偏好。

用可用的 Python 运行 `scripts/portrait_store.py`：
```text
python3 scripts/portrait_store.py list
python3 scripts/portrait_store.py save --type narrative --name restrained-profile --profile <画像.md>
python3 scripts/portrait_store.py show --type narrative --name restrained-profile
python3 scripts/portrait_store.py reset --type narrative --name restrained-profile
```

具名画像存于 `user/portraits/<type_id>/<name>.md`，反例加 `--kind negative` 存于 `user/anti-patterns/<type_id>/<name>.md`。省略 `--name` 的旧调用仍操作该文体默认文件。替换或移除前备份到 `user/history/`；脚本不可用时完成同等可恢复操作。升级保留全部用户画像与历史。

## 交付

按要求交付正文、目标文件或简短学习结果。内部取材表、文风选择过程、核验注释与 Agent 自检语言不进正文。公开来源、影响判断的不确定性，以及 PRD 需要的待决策项应清楚保留。

不附带大段写作方法说明，不自动发送或发布。效果结论以实际成稿和读者反馈为依据，脚本通过不能证明文章已有文学性。
