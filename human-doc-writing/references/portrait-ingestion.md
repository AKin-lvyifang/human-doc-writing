# 从样文学习写作

画像保存可复用的审美经验，帮助下一篇文章做选择。一篇完整样文就可以建立当前可用画像；不要要求用户凑齐一组文章，也不要把单篇特征当成整个文体的定律。

## 先识别本次意图

- “学习、记住、以后这样写、更新画像”授权提炼并保存，沿用当前请求，不例行再问确认。
- “分析一下、这次参考”只用于本次写作，不持久化。“写得好”本身也不等于保存指令。
- 正向样文提炼有效选择；反例提炼何种写法造成何种阅读问题，以及更合适的改法。用户对具体段落的评价比模型自行猜测的偏好更可靠。
- 已有同类画像时，新学到的另一种写法独立保存。只有用户明确要更新某份画像或替换默认画像，才修改对应文件；不要自动覆盖、平均合并，也不要把多种声音一并套入下一篇。

## 找到决定阅读体验的选择

先判断文章任务、读者和场合，再从下面选出对这篇文章确有作用的部分。无需逐项填满。

- **观察与作者位置**：作者注意到了什么、如何取舍材料，为什么这一点值得写；叙述离人物和读者有多近。
- **进入与推进**：读者从什么进入文章；理解、事件或情绪如何往前走；哪里展开，哪里略过，必要背景在何时补入。
- **细节与语言**：哪个动作、用词、句子节奏或意象承担了表达；修辞怎样帮助理解或感受；哪些情绪说透，哪些由材料呈现。
- **易读性**：概念出现的顺序、例子的作用、因果和过渡是否让读者跟得上。短句和少术语不是唯一依据。
- **格式与收束**：标题、段落和列表怎样照顾实际阅读；文章在哪里结束，是否还需要交代结论、行动或边界。

每条核心经验写成 **创作选择 → 读者效果 → 适用场合与边界**。用原文中可观察的做法说明理由，少写“自然、有温度、文学性强”这类无法指导创作的评价。

例如：

> 前文已通过多次行动建立人物关系，结尾停在最后一个动作，不再解释其情感含义。读者能够自行完成情绪判断。这适合材料足够的纪实与随笔；操作指南和决策文档仍须交代必要结论。

这种经验不应简化成“结尾必须短”或“不能总结”。偶然出现一次的标点、段长、句式也不升级为硬规则。必要时用一个换主题的原创小例子说明差别，并标明虚构示例；不要复刻样文独特句子、意象或经历。

## 保存与选择

一般按文体选择类型，给写法取稳定的短名，并在画像正文写适用场合。例如：

```bash
python3 scripts/portrait_store.py save --type essay --name warm-observation --profile /absolute/path/portrait.md
python3 scripts/portrait_store.py list
python3 scripts/portrait_store.py show --type essay --name warm-observation
```

- 同类型不同名称可以并存。保存到同一名称前自动备份，其他画像不受影响。
- 省略 `--name` 保持旧接口，保存为该类型的默认画像；仅在已明确选择建立或替换默认画像时使用。旧有平台类型和默认画像继续可读。
- 写作时按当前任务选择最相关的一份画像；其他画像仅在有明确补充作用时取其局部经验。具体优先级遵循主 Skill 的当前请求和偏好规则。
- `list` 只读扫描并显示路径；`save` 和 `reset` 更新索引。`reset` 只移除指定画像，先留备份；移除具名画像后，默认及其他写法仍可选。恢复时把备份作为 `--profile` 保存到原类型和名称。

支持的文体类型为 `explainer`、`product-doc`、`how-to`、`prd`、`github-readme`、`github-release`、`commentary`、`narrative`、`essay`。`wechat-article`、`xiaohongshu`、`social-article` 保留兼容。名称使用小写英文字母、数字和连接各段的连字符。

## 材料边界与完成标准

能读取完整正文再建立画像。只能看到摘要或截断内容时，说明材料限制并先完成能做的局部分析；不绕过登录、验证码或付费限制。来源记录标题、URL 或文件名，不保存原文全文和长摘录。

保存后应能回答：这份写法适合什么任务；哪些选择使它有效；什么时候不适合用。明确排除原作者身份、经历、事实、数据、观点和标志性表达的自动迁移。下一次文章中的事实仍须来自下一次任务材料。
