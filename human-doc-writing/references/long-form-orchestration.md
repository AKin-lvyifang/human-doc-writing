# 长文与复杂文档编排

## 核心原则

长文质量不取决于“一个 Agent 还是多个 Agent”，而取决于是否始终有人负责全文。

主 Agent 是主编，负责统领目标、读者、结构、术语、事实标准、叙事主线和最终文本。子智能体只处理边界清楚、可以独立完成的工作。不要把章节平均分包后直接拼接，那会得到语气漂移、事实重复和互相矛盾的“多人合租文档”。

## 先判断文档形态

### 1. 连续叙事型

适合：说明文、观点文、公众号、案例复盘、需要持续论证的文章。

特征：

- 后一部分依赖前一部分的铺垫。
- 语气、节奏和论证连续性很重要。
- 章节不能随意交换顺序。

处理：

- 主 Agent 写全部最终正文。
- 子智能体可做来源梳理、反方审查、事实核对、案例校验和风格检查。
- 不把正文按小标题分给多个子智能体独立写。

### 2. 模块化长文

适合：白皮书、产品全景、长 README、完整 PRD、手册、系统说明。

特征：

- 各模块可以独立研究，但共同服务一个统领目标。
- 读者可能跳读，需要清楚导航和统一术语。
- 模块之间仍有依赖、状态口径和重复风险。

处理：

- 主 Agent 先建立文档契约、目录骨架和模块边界。
- 子智能体按来源域、事实域或大模块工作，不按每个小标题分包。
- 默认返回“模块包”，必要时才返回分模块草稿。
- 主 Agent 统一写入最终文件，补充过渡并重做全文编辑。

### 3. 多交付物

适合：产品概览 + 安装教程 + 命令参考 + Release，或面向不同读者的多份内容。

特征：

- 读者、使用时机、更新频率或发布平台明显不同。
- 合并后会迫使读者穿过大量与自己无关的信息。

处理：

- 先定义每个文件的用途和相互链接。
- 可让不同子智能体负责不同交付物。
- 主 Agent 维护共享术语、事实口径、导航和去重。

## 什么时候使用子智能体

核心条件只有一个：存在至少两个真正独立、边界清楚的工作单元，并行收益明显高于协调成本。常见信号：

- 有两个以上可以独立完成的来源域、事实域或模块。
- 来源很多，直接塞进主线程会产生大量中间噪音。
- 不同模块需要不同角度核验，例如产品事实、安全边界、版本状态。
- 需要并行做事实核对、反方审查或一致性检查。
- 单 Agent 先后处理会明显拖慢任务，且并行结果容易汇总。

不要因为篇幅长、标题多或“看起来复杂”就使用子智能体。短文、强叙事文章和高度耦合的论证通常由单 Agent 更好。

通常使用 2～4 个边界清楚的子智能体。不要一节一个，也不要让数量超过真正独立的工作单元。

## 子智能体的默认角色

### 来源地图

返回：

- 可证实事实和来源位置。
- 已实现、实验、规划和推断的区分。
- 来源冲突、缺口和过期信息。
- 不进入正文的噪音。

### 模块分析

返回“模块包”：

```text
模块目的：
读者在此处要解决的问题：
必须写入的事实及来源：
关键判断或因果：
需要的例子、表格或图示：
边界和不确定性：
与其他模块的依赖：
可能重复的内容：
建议结构：
```

模块包默认不是最终文案。

### 怀疑型审查

返回：

- 证据不足的结论。
- 自相矛盾或跨模块口径不一致。
- 被夸大的承诺。
- 被遗漏的反例、限制或风险。

### 一致性编辑

返回：

- 术语、状态、时间、数字和读者称呼的不一致。
- 重复段落和同义改写。
- 缺少过渡或导航的位置。
- 不符合当前画像或避坑画像的片段。

## 并行写作边界

- 最终目标文件只由主 Agent 修改。
- 子智能体优先只读；需要草稿时写入临时文件或在返回中给出。
- 以磁盘上的目标文件和已确认材料为真值；对话摘要、子智能体口头结论和临时草稿不能替代最终文件。
- 多个子智能体不得竞争写同一路径；共享术语表、目录骨架、事实底稿和最终文件只能由主 Agent 或明确 owner 写入。
- 连续叙事型文章不让子智能体分别写最终章节。
- 模块化文档允许分模块草稿，但必须先共享同一份文档契约和术语表。
- 主 Agent不能直接拼接。必须比较结果、解决冲突、统一信息密度和语气，再重写成一篇完整文档。
- 长任务超时或中断时，先交付已完成范围、未完成范围、证据路径和下一步，而不是假装全量完成。

## 主 Agent 的整合顺序

1. 固定统领目标、读者和文档形态。
2. 建立目录和模块接口。
3. 分派边界清楚的子任务和返回格式。
4. 等待全部结果。
5. 对照来源解决冲突和缺口。
6. 先形成统一事实底稿，再写最终正文。
7. 做跨模块编辑：去重、术语、过渡、详略、导航和收尾。
8. 再做事实审查和画像审查。

## 拆分判断

不要按字数或标题数量拆分。重点看以下差异：

- 读者是否不同。
- 阅读时机是否不同。
- 读者要完成的动作是否不同。
- 更新频率和维护责任是否不同。
- 公开范围、权限或证据标准是否不同。
- 是否需要完全不同的表达形态。

差异小：保留为同一长文的模块、附录或索引。

差异大：拆成多个交付物，并由主 Agent 维护导航和一致性。
