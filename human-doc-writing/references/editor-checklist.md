# 通用编辑检查表

## 文档契约

- [ ] 已确定主类型、统领目标、读者和阅读场景。
- [ ] 多个内容模块共同服务统领目标，没有因为标题多就机械拆分。
- [ ] 需要拆分时，依据是读者、用途、更新方式或证据边界，而不是篇幅。
- [ ] 事实、术语、能力边界和发布条件已经核对。
- [ ] 声称“已验证”“已通过”“可发布”时，已有命令、文件或来源证据；没有把脚本存在当成脚本已运行。

## 事实与材料门

- [ ] 已区分现实、虚构或混合写作，现实部分没有被创作细节冒名。
- [ ] 非虚构中长文的篇幅与材料相称；社媒长文达到 1,200 字时，至少有五件能组成实际过程的具体材料及来源。
- [ ] 没有把同义改写、假设人物、装饰细节、抽象推演和比喻算成新材料。
- [ ] 作者位置清楚，没有把查资料写成亲历，把猜测写成内幕。
- [ ] 材料不足时已经研究、追问或缩短，没有用重复解释补字数。

## 画像

- [ ] 有用户画像时，已读取对应正向画像。
- [ ] 有避坑画像时，已逐项检查。
- [ ] 没有用户画像时，才使用内置类型卡。
- [ ] 没有复制画像来源的事实、观点、标题、句子、比喻或故事。

## 长文编排

- [ ] 主 Agent 保持了全文结构、术语、叙事主线和最终文件所有权。
- [ ] 子智能体只处理边界清楚、可以独立完成的工作。
- [ ] 所有子智能体结果已经等待、比较并解决冲突。
- [ ] 最终文本不是分段草稿的直接拼接。
- [ ] 跨模块重复、跳跃、矛盾和缺失过渡已经处理。

## 内容

- [ ] 重要内容比次要内容更突出。
- [ ] 事实、判断、推断、实验和规划没有混写。
- [ ] 没有凭常识补充功能、承诺、经历、数据或案例。
- [ ] 平台表达没有破坏统领目标，例如把教程写成宣传帖。
- [ ] 面向非技术读者时，术语、命令、路径和配置项首次出现已说明用途和价值。
- [ ] 成稿没有内部 source 注释、待核实标记、过程说明、路由指令或 Agent 自检语言。
- [ ] 每个主要段落都有新事实、动作、例子、区别或后果；只有“进一步解释”的段落已合并或删除。
- [ ] 同一中心判断没有在开头、小节和结尾换概念名反复定义或收束。
- [ ] 现实稿没有凭空增加精确天气、神态、对白、房间摆设和人物心理。

## 语言

- [ ] 开头没有“文档定位”“本文将”或空泛时代背景。
- [ ] 没有连续使用同一种“不是……而是……”结构。
- [ ] 抽象词已经落到具体事实、动作或例子。
- [ ] 连续段落没有相同开头和相同节奏。
- [ ] 列表只装真正并列、步骤或需要扫描的信息。
- [ ] 没有把同一个意思写成正文、列表和总结三遍。
- [ ] 没有为了像人故意加入假经历、错别字、网络梗或无关情绪。
- [ ] 读者追问只用于内部排序；正文没有作者自设问句、紧接着自答或用疑问句充当转场。
- [ ] 已圈出所有单独截图显得有力、放回正文却没有新增事实、解释或情绪的句子，并删除只剩点题姿势的短句。
- [ ] 表格用于对比、映射、规则、状态；步骤列表用于操作顺序，没有为了显得完整而堆格式。
- [ ] 约 1,200 至 2,000 字的公众号连续叙事稿已删掉全部小标题试读；仅恢复确有导航作用的标题。
- [ ] 没有靠粗口、错别字、网络梗、固定口头禅、假情绪或生活道具表演活人感。
- [ ] 主语和动作没有被长前置成分与多层“的”压到句尾。
- [ ] 普通段落没有按同一短句鼓点收尾，单句段确实需要停顿。
- [ ] 公众号稿没有用问号、反问、自问自答、抽象金句和动作借喻制造发现感；已运行 `wechat-longform` 检查档。
- [ ] 结尾没有重复摘要、强行回环、硬升华或自动添加运营口播。

## 编辑

- [ ] 已完成一次脱离原结构的独立删改。
- [ ] 开头、信息推进和收尾符合当前画像。
- [ ] 能缩短的地方已经缩短，事实没有丢失。
- [ ] 最终文本像主编在组织信息，不像多个模型轮流填栏目。
- [ ] 已按 `human-voice-gate.md` 完成七遍终审与最后冷读。
- [ ] 已运行与类型对应的 `lint_ai_style.py` profile，并修复所有阻断项。
- [ ] 脚本警告已逐项人工判断，没有把“脚本通过”当作事实和人味通过。
