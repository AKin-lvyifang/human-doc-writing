# 人味统一终审

这道门适用于所有写作类型。它不提供固定文风，也不替代用户画像。画像决定文章在什么场景怎样说话，这道门保证事实、材料、推进和中文表达没有被“完成任务的姿势”替代。

## 使用顺序

1. 动笔前执行事实与材料门。
2. 按类型卡和当前画像写第一稿。
3. 初稿完成后执行七遍终审。
4. 运行对应检查档。
5. 根据检查结果修改，再做最后冷读。

不要在动笔前加载全部禁词并逐句躲避。第一稿先靠材料和说话位置成立，详细清理留到初稿之后。

## 事实与材料门

### 先确定作品对现实作出什么承诺

- 现实写作：真人、现实事件、数字、引语、产品状态和用户经历都要能说明来路。用户没有提供的亲历、现场、对白和心理不能补成事实。
- 虚构写作：可以创造人物、地点、现场、对白、心理和结局，但人物目标、行动、因果、时间和世界规则要前后接得上。
- 混合写作：先分开必须准确的现实部分和获准创造的部分，不能让创作细节冒充现实证据。

### 现实稿先数材料

可用材料包括用户明确提供的事实、动作、数字、原话与判断，以及已经查到并能核验的案例、数据、产品流程、人物经历和时代条件。

下面这些不算新材料：

- 同一个观点的同义改写。
- 模型临时想出的“普通用户”或“比如有个人”。
- 没有来源的典型场景、天气、神态、对白和房间摆设。
- 只由上一段继续推演出来的用途、意义、风险和未来。
- 为抽象概念换一套比喻。

非虚构中长文计划达到 1,200 字时，内部至少列出五件具体材料，并标明来自用户哪句话、哪个文件或哪个可靠来源。五件材料还要能组成一个实际过程、冲突或因果关系，不能只是五条相邻观点。

材料不足时只走一条路：

1. 公开事实可查时先研究，研究后重新计数。
2. 依赖用户经历、情绪或私人判断时，一次问完最多三个问题，不同时交一篇空稿。
3. 用户要求直接写且无法补材料时缩小题目。最多交一篇约六百字的短答，宁可短，也不注水。

教程、README、PRD 和产品文档不机械执行“五件材料”。它们改为检查读者任务、事实来源、步骤、状态、限制和可验证结果是否足以支撑交付。

## 动笔前找到说话位置

在内部回答五件事，不把答案原样交给用户。

1. 谁在说。他凭什么知道，哪里只是在推测。
2. 哪件事让他现在想说。
3. 手里哪些动作、数字、时间、地点、原话、失败、代价和结果能托住文章。
4. 他对什么有明确判断，依据在哪里，边界到哪里。
5. 读者知道上一段以后最自然会追问什么。

没有亲历不等于作者必须消失。作者可以写自己怎样选材料、哪条证据改变了判断、哪里仍拿不准。第一人称判断不能冒充第一人称经历。

第五项只在内部决定下一段先写什么。不要把内部追问原样写成“问题来了”“该选哪一个”“为什么会这样”再由作者回答。不论素材是否含有问句，公众号非虚构正文都改用陈述或间接引语推进。

## 第一稿怎样往前走

- 开头尽快碰到具体事情、问题、动作或结果，不预告全文结构。
- 一段先完成眼下的一件事。后一段接住前一段留下的人、物、动作、结果或问题。
- 公众号现实观点稿用陈述句推进。先写发生了什么，再写哪里造成阻碍、为什么会这样、接下来怎样处理。读者的理解断口放在信息顺序里解决，不用反问、自问自答和疑问句转场制造悬念。
- 普通地方用普通句子。不要在两个事实段之间插入一句“麻烦恰好出在这种认真里”式的短判断，也不要用“成了表象”“最先需要钉住”这类抽象词和借喻假装点题。判断有实际因果就并入相邻段落写清，没有新增内容就删掉。
- 新段落必须增加新事实、新动作、新例子、新区别或新后果。同一观点换一种说法不算推进。
- 公众号约 1,200 至 2,000 字的观点、复盘和连续叙事稿，默认先写成无小标题版本。初稿后删掉全部小标题重读一次；只有读者确实需要定位独立步骤、明显转场或较长章节时才恢复。只负责概括下文的抽象小标题不能算导航。
- 一个概念解释清楚以后，后文接着写对应的人、事、动作与后果，不再换一个术语重新定义同一判断。面向普通读者时，内部方案名只在确实帮助理解时出现。
- 背景知识等读者需要时再出现。删掉以后人物选择、风险和结论都不变的背景，不必写。
- 先让人和动作出现，再补时间、原因、条件和例子。长句可以有，读者要尽早知道谁做了什么。
- 段落和句子保留长短差。普通地方普通地结束，单句成段只留给确实需要停一下的位置。
- 动作、物件或原话已经传出情绪时，少解释一句。留白不能藏掉关键事实和因果。
- 判断可以有偏好和情绪，把依据放在附近。材料只支持七成就说到七成。
- 写到事情讲完就停，不自动总结、升华或回到开头。只有前文持续改变了某个事物的含义，回环才有价值。

## 不要表演活人感

- 不靠“老铁”“兄弟们”、粗口、错别字、网络梗、括号吐槽和固定口头禅证明作者是人。
- 不凭空摆放深夜、烟、咖啡、雨、电话和房间细节。现实稿的细节要有来源并改变理解。
- 不按固定间隔加入自嘲、疑问句、单句段和“我也不知道”。这些表达必须来自眼前内容。
- 不替读者发问来表演交流感。公众号非虚构正文不用问号；素材里的真实提问改成不改变含义的客观处境或间接引语。
- 不靠孤立短句、反常断言和暧昧代词制造“值得截图”的深意。删掉后事实、解释和情绪没有损失，就删，不换另一句漂亮话。
- 不从一个数字想象出具体城市、职业、出租屋、心理和动作，再把这个人物当成事实或证据。
- 不用道路、战争、建筑、温度、仓储、海洋、器官等多套借喻包装同一个抽象概念。

## 初稿后的七遍终审

### 第一遍看谁在说

检查作者凭什么知道，哪一处能看出他真正关心，哪些判断有材料托着。换一个模型也能原样写出的段落，补来源、动作与取舍；没有东西可补就删。

### 第二遍看文章是否推进

给每段标出主要作用和材料来源。只写得出“进一步解释”或“可能的影响”的段落通常没有新东西。做一次压缩试验，删掉三分之一后事实、动作和判断几乎没变，保留删短版。

再给全文的中心判断做记号。同一判断如果在开头、两个小节和结尾反复出现，只保留承担新事实或新后果的那一次。不要靠更换概念名、增加定义或重新收束，把一次判断写成多轮结论。

### 第三遍拆掉表演性中文

圈出所有单独截图看起来有力、放回正文却没有增加事实、解释或情绪的句子，大部分删掉。再删除假具体、假口语、抽象名词堆叠和多套借喻。把抽象话改成谁做了什么、付出多少时间或成本、谁承担后果。

### 第四遍听中文是否顺

让主干早点出现，拆开过长定语，检查代词指向。连续短句像敲桌子就合并，长句一直没有落脚处就拆开。动作已经表达情绪时，删掉紧随其后的翻译。

### 第五遍清模型形状

删除模板化开头、写作预告、洞察路标、机械翻案句、商业黑话、重复句首、排队式短段和模板化总结。社媒中长文同时执行下方严格档。

### 第六遍核事实或设定

现实稿核时间、数字、身份、引语、因果、产品状态和第一人称动作。虚构稿核人物知道什么、时间空间、物件、伤势和世界规则。核验说明留在后台。

### 第七遍查结尾

分别删掉最后一段和最后两段再读。删掉更有力就让文章提前结束。正文没有持续处理时代、文明、未来或世界尺度时，结尾回到具体事实、行动或当前判断。

## 所有文档都执行的通用门

- 不编造事实、经历、数据、社会证明、案例和验证结果。
- 不用空泛时代背景、文档自述和写作预告开场。
- 不把同一个意思写成正文、列表和总结三遍。
- 不用“核心”“本质”“真正”“更深一层”等抬高词代替事实差异。
- 不用商业汇报黑话给普通事情抬价。术语确有精确含义时保留。
- 不让格式接管内容。标题、列表、表格和加粗只在能帮助导航、对比或执行时使用。
- 不用固定互动口播、宏大宣言或机械总结收尾。

## 社媒中长文严格档

适用于公众号、小红书、知乎、论坛、博客和其他社媒中长文。标题、小标题、正文、图片说明和引用转述都在检查范围内。

交稿前清零：

- 中文或英文冒号，以及破折号、双破折号和连接号式破折号。网址、代码和无法改动的机器字段除外。
- “不是……而是……”“并非……而是……”“不在于……而在于……”“与其说……不如说……”“不只……还/也……”“表面……实际/实则……”“看似……实际/实则……”及其变形。
- “不丢”“说白了”“说穿了”“先说结论”。
- 作为洞察路标的“更微妙的是”“还有一层”“只说对了一半”“值得注意的是”“需要指出的是”“从某种意义上说”。
- 用来给普通事情抬价的绝对禁词：赋能、抓手、商业闭环、价值闭环、闭环、能力沉淀、打法、拉通、底层逻辑、顶层设计、认知跃迁、价值释放、能力建设、降本增效、内容矩阵、全链路、组合拳、打开想象空间、想象空间、结构性机会、关键命题、深层逻辑、技术底座、公共底座、技术主权、单点风险、主脊柱、材料锚点、认知增量、迭代闭环。

“沉淀、颗粒度、对齐、协同、链路、生态位、心智、范式、方法论、核心变量”只做语境检查。确实表达化学、排版、生态学、学术或不可替代的精确概念时可以保留；只是抬价时改写。

修改违禁句时，先找它真正要说的事实，再用普通句子写出来。不要换成另一句同样漂亮的套话。

公众号现实观点、复盘和产品体验稿还要清零两类写法：

- 作者自己提出、紧接着自己回答的问句，包括开头或段首的“问题来了”“该选哪一个”“为什么会这样”。素材里的真实提问也改成不改变含义的转述；公众号正文中的问号全部改成陈述。
- 只负责停顿、翻案或显得意味深长的孤立短判断。尤其检查“恰好出在这种……里”“在这一刻成了表象”“最先需要钉住……”及同类写法。把有效因果并回上下文，删掉只剩姿势的句子。

## 技术与结构化文档适配

README、PRD、教程、Release、产品文档和说明文仍执行通用门，但保留这些必要形式：

- 表示键值、字段、定义和步骤结果的冒号。
- 代码、命令、URL、配置项和机器字段。
- 真正并列的列表、用于比较的表格、帮助跳读的标题。
- 准确且在项目中已有定义的术语。
- 能减少误解的对比句。

不要因为形式合法就保留空洞内容。一个标题下面没有新事实，一个列表只是把同一句话拆成多项，一个术语可以换成普通动作却仍被用来抬价，都需要改。

## 自动检查

所有 Markdown 或纯文本成稿都运行检查器。

```text
python3 scripts/lint_ai_style.py 稿件.md --profile universal --strict
python3 scripts/lint_ai_style.py 社媒稿.md --profile social-longform --strict
python3 scripts/lint_ai_style.py 公众号稿.md --profile wechat-longform --strict
```

`universal` 检查通用模式并保护技术文档需要的格式。`social-longform` 在通用检查之上启用散文严格项。`wechat-longform` 再拦截公众号里的作者自设问句和表演性点题。脚本只发现形状，硬项以外的警告需要人工判断；脚本通过也不代表事实、材料和人味已经通过。

## 最后冷读

暂时忘掉所有规则，只回答五个问题。

1. 哪里让我相信作者确实知道这件事。
2. 哪里让我愿意继续读。
3. 哪一段像人在处理一个问题，哪一段像模型在完成写作任务。
4. 哪句话说得比材料大。
5. 文章在哪一句已经结束。

有一个问题答不上来，就回到对应段落再改。
