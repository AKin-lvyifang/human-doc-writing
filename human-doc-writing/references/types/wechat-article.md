# 类型写作卡：公众号文章 `wechat-article`

## 适用范围

适合微信公众号长图文。重点是沿一个中心判断、问题或叙事主线完成连续阅读，不是把说明文切成很多短句，也不是把小红书笔记拉长。

常见子类型：

- `opinion`：观点与判断。
- `case-study`：案例拆解。
- `tutorial`：有解释深度的教程。
- `review`：项目或阶段复盘。

## 读者结果

读者带走一个清楚的判断、方法或行动框架，并知道它依据什么。文章可以讨论多个方面，但每一部分都要推动同一条主线。

## 写前必须确认

1. 中心判断、问题或叙事主线。
2. 读者已有认知和争议点。
3. 可用案例、数据和第一手材料。
4. 希望读者读完后理解、判断或采取什么行动。

写前执行 `../material-gate.md`，再读取 `../natural-social-prose.md`。计划达到 1,200 字的非虚构稿至少要有五件能组成实际过程的具体材料；不足时先研究、追问或缩短，不用同义改写撑篇幅。材料足够时把约定篇幅下界写进契约，终审不能静默交付更短的稿子。

## 可选推进动作

下面只用于理解不同材料可能怎样推进，不是三套固定提纲。不要把箭头逐格变成相同段落数。

### 观点文可能经过

具体冲突或现象 → 中心判断 → 多组论证 → 反例或边界 → 结论与行动。

### 案例文可能经过

结果或异常 → 背景 → 关键决策 → 过程证据 → 成败原因 → 可迁移的方法。

### 教程文可能经过

读者问题 → 方法全景 → 关键步骤 → 原理和常见误区 → 适用边界 → 行动清单。

## 标题与开头

- 标题给出具体对象、矛盾或结果，不制造无法兑现的悬念。
- 开头尽快进入场景、事实或冲突。
- 现实观点稿使用陈述式标题和开头。不要用疑问标题、自问自答或“然后问题来了”充当钩子；材料里的问题改成读者处境、选择困难、理解障碍或间接引语。
- 前几段按普通顺序说清发生了什么、执行过程怎样、哪里没有推动结果。不要在事实段之间插入孤立的点题短句。
- 作者可以很早给出普通判断，也可以先讲一段过程再判断。不要让三篇稿件都在相同段落完成边界说明和中心结论。
- 不用空泛时代背景或无证据的“很多朋友问我”。
- 没有真实个人经历时，不伪装成亲历者。
- 约 1,200 至 2,000 字的观点、复盘和连续叙事稿默认不用小标题。初稿后做一次“删掉全部小标题”的试读；正文仍能自然推进就保留无标题版本。教程、明确分条的方法文或读者确实需要定位时可以保留必要标题。

## 正文

- 多个观点或案例必须共同服务中心主线，不能中途变成功能清单。
- 判断要有案例、事实、推理或明确经验来源。
- 把“读者接下来会问什么”留在内部。下一段直接补原因、证据、边界或处理办法，不把理解顺序写成作者发问、作者回答的表演。
- 默认沿用独立 `human-writing` 的普通白话推进：具体事实与动作在前，边界和判断跟在材料后面，解决办法落到可以执行的动作。不要为融合版额外增加悬念、发现弧、金句或“更深一层”的作者姿势。
- 保留来自材料的普通判断、补充、自我修正和短暂岔话。它们确实帮助读者理解时，不要为了整齐全部删成中性说明。
- 事实核验留在后台。只在会改变结论的位置说明一次边界，不用“这里能够确认的是”“文章只讨论”反复证明谨慎。
- 少写“几项分别负责什么、共同构成什么”的方案说明。先写人或系统做了什么、为什么没起作用、结果怎样变化；分类只在确实帮助理解时出现。
- 写 Skill、系统、方法和工作流时，优先沿一次真实安装、使用、失败、取舍或修改展开。概念等动作需要时再解释，解释完继续写它改变了哪一步。
- 单句成段只有在删掉会损失真实情绪或行动转折时才保留。只负责显得意味深长、截图好看或替上下文点题的短句直接删除；有效因果并回相邻段落。
- 小标题帮助转折和导航，不追求整齐排比。
- 不用小标题和新的抽象名词反复命名同一个中心判断。术语第一次出现时用普通话解释，后文回到具体对象、动作和结果。
- 段落可以比正式说明文短，但不要每句话都单独换行。
- 段落长短跟着材料密度变化，不预设总段数。复杂过程可以放开写，已经说清的地方可以很快过去。
- 去掉 AI 腔以后若文章变薄，从材料补回过程、条件、选择和后果，不用抽象解释或重复结论补篇幅。
- 写前材料覆盖表里的必须保留项要在终稿中逐项可见。约 1,200 字以上的现实长稿只剩定义、职责和结论时，退回过程重写，不能只靠总字数放行。
- 对反例和限制给足篇幅，避免绝对化。
- 强叙事文章由主 Agent 统一写正文；子智能体更适合做资料梳理和反方审查。

## 结尾

用判断、方法或具体行动收束。除非账号运营明确要求，不自动添加固定互动口播。

## 语言与节奏

有人味，但不假装熟络。可以有作者判断和有限情绪，不能凭空制造经历、对话和读者反馈。普通事情用普通句子说清，作者不替文字安排反问、顿悟和余味。

## 常见 AI 痕迹

- 开头用时代背景和宏大趋势铺垫。
- 开头或段首先问“该选哪一个”“为什么会这样”，随后自己回答。
- 在两个事实段之间插入“麻烦恰好出在这种认真里”“工具数量成了表象”一类孤立判断，事实没有增加，只增加点题姿势。
- 用“钉住”“抓住”“撕开”“刺穿”等动作借喻包装本可直接陈述的范围、边界和原因。
- 排比小标题整齐到像季度汇报。
- 每节先预告、再列表、再总结。
- 为了亲切虚构“朋友问我”“我亲测”。
- 多个章节分别写得完整，却没有一条贯穿全文的主线。
- 结尾重复全文并升华使命。

## 交付检查

- [ ] 全文有清楚的中心判断、问题或叙事主线。
- [ ] 多个方面都在推进主线，没有平行堆料。
- [ ] 开头在较短篇幅内进入具体问题。
- [ ] 没有作者自设问句、自问自答或问号；素材里的真实提问已改成不改变含义的间接表述。
- [ ] 没有孤立的假深刻短句；每个保留的单句段都有事实、情绪或行动转折。
- [ ] 关键判断有证据或推理。
- [ ] 标题和小标题没有透支内容。
- [ ] 约 1,200 至 2,000 字的连续叙事稿已做无小标题试读，保留下来的标题确有导航作用。
- [ ] 材料足够时已达到文档契约中的篇幅下界，并运行 `--min-han`；没有因终审过度压缩。
- [ ] 中心判断没有在开头、多个章节和结尾换词重复。
- [ ] 没有虚构第一手经历和社会证明。
- [ ] 每个主要段落都带来新事实、动作、例子、区别或后果。
- [ ] 段落没有被修成相同长度和单一功能；同批多稿没有共用相同段落数与推进骨架。
- [ ] 正文没有连续的核验声明、文章范围声明或方案说明书口吻。
- [ ] 已执行 `../human-voice-gate.md` 的七遍终审和最后冷读。
- [ ] `lint_ai_style.py --profile wechat-longform --strict` 已通过，阻断项为零。
