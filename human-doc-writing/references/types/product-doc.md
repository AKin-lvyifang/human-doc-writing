# 类型写作卡：产品文档 `product-doc`

## 适用范围

适合产品概览、产品说明、设计说明和面向用户的白皮书。重点是帮助读者理解产品、评估是否适合，以及知道下一步去哪里。

常见子类型：

- `overview`：产品概览。
- `design-explainer`：设计取舍和工作方式。
- `whitepaper`：有证据、有边界的系统说明。
- `manual-whitepaper`：兼具产品白皮书和说明书，既帮助读者评估产品，也帮助读者安装、配置、使用和排障。

## 读者结果

读者知道产品解决什么、如何工作、关键限制是什么，并能决定是否继续安装、试用、评审或深入阅读。

## 写前必须确认

1. 统领目标、主要读者和阅读场景。
2. 当前已实现、实验和规划能力。
3. 哪些内容需要正文展开，哪些适合附录、索引或独立参考页。
4. 可核验的事实来源。

白皮书涉及行业数据、市场规模、法规、价格、版本或趋势判断时，还要确认：

- 核心数据是否有来源名称、发布机构和年份。
- 数据是否足够新；过旧数据必须说明为什么仍可用。
- 预测性数据是否标注为预测，并说明预测口径或方法。
- 关键结论是否能从正文证据直接推出，没有额外偷加假设。
- 同一指标在全文是否使用同一来源和口径。

## 可选结构

### 产品概览

用户问题 → 产品如何介入 → 核心工作流 → 关键能力 → 边界 → 下一步。

### 设计说明

背景问题 → 设计原则 → 关键取舍 → 系统协作 → 代价与边界 → 当前状态。

### 白皮书

问题与证据 → 目标和非目标 → 工作模型 → 多个核心机制 → 安全与治理 → 当前验证 → 限制与后续。

白皮书可以系统覆盖多个方面。关键不是章节少，而是所有模块都服务同一个评估目标，并具有明确层级、导航、证据和交叉引用。

### 产品说明书型白皮书

产品定位 → 目标用户 → 技术或权限边界 → 安装与配置 → 验证安装 → 核心功能 → 使用流程 → 常见问题与注意事项 → 版本适用范围。

这种结构适合读者既要判断产品是否适合，又要马上上手使用的文档。前半部分帮助判断，后半部分帮助操作；不要让命令、路径和版本号抢走产品定位，也不要让功能清单替代真实工作流。

## 开头

从用户真实问题、使用场景或产品事实开始。产品名不必连续充当每段主语。不要先解释“这是一份什么文档”。

## 正文

- 以读者任务、工作流和决策问题组织，不按代码模块机械盘点。
- 重点解释关键机制和取舍，普通功能按重要性处理。
- 功能说明优先采用“作用 / 使用方式 / 注意事项或边界”。重要功能展开，次要功能压缩。
- 当前能力、实验能力和路线图分别标记。
- 命令、安装、API 等细节根据阅读场景放在正文、附录或独立参考页，不机械拆分，也不全部塞进主线。
- 面向非技术读者时，术语、命令、路径和配置项首次出现要补一句用途和价值。
- 表格承载对比、映射、规则、状态和数据流向；步骤列表承载操作顺序；FAQ 可按“现象 / 说明或原因 / 解决方法 / 反馈信息”组织。
- 涉及安全、隐私、本地文件、API 密钥、后台任务、实验功能和版本状态时，显式说明数据流向、触发方式、默认状态和风险边界。
- 涉及数据或趋势时，用“结论 / 证据 / 解释”组织段落。没有证据支撑的判断宁可删掉或改成不确定表述。
- 多模块长文先建立术语表和状态口径，再并行核对事实。
- 只写来源可以证实的承诺。

## 结尾

给明确下一步，或停在限制和适用条件。没有必要时不写空泛愿景。

面向产品说明书或白皮书时，结尾可以停在版本适用范围、官方来源、反馈渠道或下一步操作。产品会持续变化时，说明本文基于哪个版本或日期，以及后续变更以哪里为准。

## 语言与节奏

像产品负责人向同行解释：具体、有判断、能承担取舍。模块可以长短不一，不为了对称给每个功能配同样篇幅。

## 常见 AI 痕迹

- “一句话说明”“适合谁”“不要误解成什么”自动成章。
- 每个功能都配一段意义升华。
- 同一卖点在理念、功能、边界和总结中反复出现。
- 把路线图写成已发布能力。
- 大量同级标题没有层次，正文退化成栏目清单。
- 多个子稿直接拼接，术语、状态和语气互相漂移。

## 交付检查

- [ ] 全文有一个清楚的统领目标。
- [ ] 多个模块具有层级、导航和相互关系。
- [ ] 读者能在前两段知道产品解决什么。
- [ ] 关键工作流和取舍比功能盘点更清楚。
- [ ] 当前、实验、规划没有混写。
- [ ] 细节放置依据阅读场景，而不是机械拆分或全部堆入正文。
- [ ] 术语、命令、路径和配置项首次出现时，已说明用途和读者价值。
- [ ] 核心数据有来源名称、发布机构和年份；预测性数据有预测口径。
- [ ] 关键结论能从正文证据推出，没有无来源的绝对化表述。
- [ ] 功能节没有平均用力，重要功能有作用、使用方式和边界。
- [ ] 最终稿没有内部 source 注释、待核实标记、过程说明或 Agent 自检语言。
