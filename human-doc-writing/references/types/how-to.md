# 类型写作卡：教程与帮助 `how-to`

## 适用范围

适合快速开始、单任务教程、帮助中心和故障排查。单篇任务指南重点是让读者完成一个可验证的动作；完整手册可以由多个独立任务模块组成，但需要清楚导航。

常见子类型：

- `quickstart`：最短路径跑通。
- `task-guide`：完成一个具体任务。
- `troubleshooting`：从症状定位并解决问题。

## 读者结果

读者照着做能得到明确结果，并知道如何确认成功。

## 写前必须确认

1. 前置条件。
2. 目标结果。
3. 操作环境和版本。
4. 失败时最常见的原因。

## 可选结构

### 快速开始

结果预览 → 前置条件 → 最少步骤 → 验证成功 → 下一步。

### 任务教程

任务说明 → 准备 → 编号步骤 → 每个关键步骤的预期结果 → 完成检查。

### 故障排查

症状 → 最可能原因 → 按低成本顺序排查 → 修复 → 如何避免再次发生。

## 开头

先说读者最终会完成什么，以及大致需要什么。不要先讲产品历史、理念或完整功能。

## 正文

- 操作步骤使用编号。
- 一个步骤只包含一个主要动作。
- 命令、路径和按钮名称必须准确。
- 关键步骤后写预期结果。
- 高风险动作先给备份或恢复方式。
- 原理只解释到足以避免误操作的程度。

## 结尾

用可验证结果、下一步或相关文档链接结束。不要总结每个步骤。

## 语言与节奏

直接、可执行。避免“轻松实现”“只需简单几步”等未经验证的承诺。

## 常见 AI 痕迹

- 把教程写成产品介绍。
- 每一步都加“这样做可以确保……”。
- 步骤缺少前置条件和成功标志。
- 命令示例看起来合理但没有来源。
- 故障排查按概念分类，而不是按成本和概率排序。

## 交付检查

- [ ] 单任务指南有明确结果；多任务手册有清楚的模块入口和导航。
- [ ] 前置条件、版本和权限明确。
- [ ] 所有命令和路径可核验。
- [ ] 关键步骤有成功标志。
- [ ] 失败路径和恢复方式足够清楚。
