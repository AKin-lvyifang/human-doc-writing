# GitHub 发布说明 `github-release`

## 读者要得到什么

知道某个版本实际变了什么、哪些变化影响自己、是否需要升级或迁移，以及有哪些相关已知问题。

## 始终覆盖的内容底线

- 版本范围、日期和变化有真实依据；未合入、未发布与未来计划不能混写成该版本已交付能力。
- 用用户可辨认的场景说明重要变化及影响，内部重构是否改变行为应据实判断。
- 破坏性变化、兼容性与迁移要求醒目呈现；必要升级动作准确可执行。
- 相关已知问题与限制不隐去，未知验证结果不写成“已解决”或“全面支持”。

## 可选推进与表达

可以围绕一项重要改进展开，也可以按用户任务归组。小补丁直接说明触发条件与修复后行为即可，不补无内容的栏目。完整变更链接用于追溯，不能代替用户影响说明。

允许简洁而有温度的声音。用真实的前后变化表达价值，重要迁移事项用清楚的条件与动作表达，不能被标题、庆祝口吻或文学化描写掩盖。

## 按阅读效果验收

用户能否确认这次变化是否与自己有关，找到需要做的事，并理解升级代价？版本边界和已知问题是否真实清楚？
