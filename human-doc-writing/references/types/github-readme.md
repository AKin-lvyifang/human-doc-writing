# GitHub README `github-readme`

## 读者要得到什么

第一次到访的人能判断项目是否相关，找到最短上手路径或合适的深入资料。

## 始终覆盖的内容底线

- 项目用途、目标使用者和当前可用状态准确。
- 给与项目性质相符的上手入口或最小示例，以及必要环境、版本和兼容性条件。可操作部分遵守 [how-to](how-to.md) 的要求。
- 安装命令、配置、示例和链接与真实项目一致，不自动补出不存在的能力或渠道。
- 交代会影响使用决定的主要限制；许可证、贡献和支持入口按已知项目资料提供，不编造。

## 可选推进与表达

工具库可以让最小代码例子先说话；应用可以用界面和任务场景说明用途；研究项目可以先讲研究问题与复现入口。让相关性判断和上手入口容易找到，详细架构或完整 API 按需要链接出去。

语气可专业、亲切或略带个性。具体例子承担吸引力，标题和段落帮助扫描；品牌声音不能盖过安装条件、功能状态和限制。

## 按阅读效果验收

新访客是否看得懂项目用途、找得到上手方式，并能分清已有能力与计划？示例是否足够真实，深入阅读是否有可用入口？
